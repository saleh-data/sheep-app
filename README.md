# إدارة الأغنام

تطبيق عربي باتجاه RTL، مبني بـ Next.js + TypeScript + Tailwind CSS، ومكونات shadcn/ui محلية مخصصة تعتمد على Radix، وأيقونات Lucide. الخلفية Supabase PostgreSQL وAuth وStorage وEdge Functions. الواجهة تصدَّر إلى ملفات ثابتة؛ جميع البيانات والحسابات والحماية تعمل في الخلفية الحقيقية. صالح للنشر على Cloudflare Pages دون خادم Next.js أو خدمات مدفوعة.

## حالة التسليم

- تم بناء الواجهة الوظيفية للصفحات الرئيسية الثلاث: الرئيسية، العمليات، رأس المال.
- تم تطبيق ترحيلات قاعدة البيانات على مشروع Supabase `Sheep`، ونشر دالة `upload-attachment`.
- المخزون والأرصدة وجميع سجلات الأعمال تبدأ من صفر. لم تُضف معاملات أو شركاء تجريبيون إلى المشروع الحقيقي.
- `/preview/` معاينة منفصلة ببيانات فارغة، ولا تقرأ بيانات العمل ولا تحفظ شيئًا، حتى لو كان الزائر مسجّلًا.
- `/` التطبيق الفعلي: يتطلب حساب Supabase معتمدًا في جدول الشريكين.
- الدخول بالبريد وكلمة المرور للحسابين اللذين ينشئهما المالك من Supabase Auth مع Auto Confirm User. القائمة private.signup_allowlist تحصر الاعتماد بالبريدين المحددين. لم يتم إنشاء حسابات أو اختيار كلمات مرور نيابة عن الشريكين.
- موقع المراجعة الخاص في ChatGPT لا يحل محل النشر المستقل على حساب Cloudflare. يحتاج الشريك إلى رابط Cloudflare مستقل بعد إكمال الإعداد.
- لا يعتبر التسليم إطلاقًا تشغيليًا مكتملًا قبل اختبار حسابي الشريكين ورفع الصور فعليًا على iPhone.

## التشغيل

استخدم Node.js 22 أو أحدث:

```bash
npm ci
npm run dev
```

افتح `http://localhost:3000` أو `http://localhost:3000/preview/` لمعاينة الشكل.
يحتوي `lib/project-config.ts` على عنوان مشروع Sheep ومفتاحه **العام publishable فقط**. هذه بيانات اتصال عامة، وليست صلاحية إدارية؛ لا تضع مفتاح service-role أو secret في المتصفح أو متغير `NEXT_PUBLIC_`.

لربط مشروع آخر، انسخ `.env.example` إلى `.env.local` واملأ:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_PUBLISHABLE_KEY
```

## النشر على Cloudflare Pages — مجاني

1. أنشئ حساب Cloudflare بالخطة المجانية؛ لا تحتاج إلى دومين خاص.
2. جهّز Supabase باتباع `docs/DEPLOYMENT.md`.
3. نفّذ `npm ci` ثم `npm run build`.
4. من Workers & Pages اختر إنشاء تطبيق Pages، ثم Direct Upload. ارفع محتويات مجلد `out` أو ملف ZIP يحتوي هذه المحتويات في جذره.
5. استخدم نطاق `pages.dev` المجاني مع HTTPS. لا يحتاج هذا المشروع إلى Next.js SSR أو Pages Functions أو OpenNext.
6. إذا ربطت مستودع Git، أمر البناء `npm run build` ومجلد الإخراج `out`. اضبط متغيرات الاتصال العامة في إعدادات البناء إذا أردت تجاوز `lib/project-config.ts`.
7. ضع عنوان الموقع الفعلي في إعدادات Supabase Auth، وعطّل Allow new users to sign up من إعدادات Auth؛ أنشئ الحسابين إداريًا كما في دليل الإعداد.
8. جرّب الدخول بالحسابين، ثم أضف مساهمة فعلية وسجّل عملية فعلية فقط عندما تصبح جاهزًا.

أمر `npm run deploy` متاح أيضًا، ويشغّل Wrangler. اكتشف أوامر الإصدار الحالي بـ `npx wrangler --help` وسجّل الدخول في جهازك. لا يختار السكربت خطة مدفوعة أو دومينًا مدفوعًا.

> `next start` غير مناسب لتصدير `output: export`. استخدم `npm run dev` أثناء التطوير، ثم قدّم مجلد `out` بخادم ملفات أو Cloudflare Pages بعد البناء.

## الحسابات والصلاحيات

- حسابان فقط: `partners.slot` يقبل 1 أو 2 مع قيد فريد.
- لكل حساب بريد معتمد يطابق بريد `auth.users` الحالي والمؤكد.
- الشريكان يشاهدان ويضيفان ويعدّلان ويحذفان جميع عمليات المشروع وحركات رأس المال. لا توجد أدوار إدارية إضافية في الواجهة.
- اختيار الشريك في رأس المال يعني صاحب المساهمة/السحب، بينما منفّذ الإدخال يُسجّل تلقائيًا.
- الإنشاء والتعديل يسجلان هوية المنفّذ، والوقت، ورقم الإصدار. جدول مراجعة داخلي يحتفظ بالحالة قبل التعديل وبعده.
- الحذف إلغاء منطقي يستبعد العملية من الحسابات. يبقى أثرها للمراجعة ولا يوجد زر استعادة في النسخة الأولى.
- المرفقات خاصة. عرضها عبر روابط موقعة مدتها دقيقتان. حذفها أو حذف العملية يخفيها من التطبيق؛ الصور محفوظة إداريًا للمراجعة وتستهلك حصة التخزين إلى أن تزال نهائيًا وفق سياسة الاحتفاظ التي يحددها المالك.
- لا يحق للعميل تغيير المخزون أو الجداول مباشرة. تُجرى الكتابة عبر RPC تتحقق من الحساب والمدخلات والإصدار والمخزون.
- جميع الجداول العامة محمية بـ RLS، والدوال ذات الصلاحيات المرتفعة داخل مخطط `private` غير معروض للـ API. أُلغيت صلاحيات EXECUTE العامة.
- خدمة رفع الصور تتحقق من JWT عبر `getUser` ومن اعتماد الشريك، ثم تتحقق من نوع الصورة وتوقيع الملف وحجمه. مفاتيح الإدارة تُقرأ داخل الخدمة فقط.

## الحسابات المالية

| المؤشر | المعادلة |
|---|---|
| المخزون | المشتريات بالعدد − المبيعات بالعدد − الهالك |
| التدفق النقدي التجاري | المبيعات − المشتريات − المصاريف |
| صافي رأس المال | المساهمات − السحوبات |
| الرصيد النقدي | التدفق النقدي التجاري + صافي رأس المال |
| متوسط تكلفة الرأس | إجمالي مبالغ الشراء ÷ إجمالي عدد الرؤوس المشتراة |
| قيمة المخزون | عدد الرؤوس المتبقية × متوسط تكلفة الرأس |
| صافي الربح | المبيعات + قيمة المخزون − المشتريات − المصاريف |

قيمة الهالك التقديرية مرجع تحليلي فقط ولا تخصم من النقد أو الربح. صافي الربح يُحسب بتقييم المخزون بمتوسط تكلفة الشراء المرجّح لجميع المشتريات منذ البداية؛ ليست هذه قيمة السوق أو تكلفة رأس محدد. الرصيد النقدي يمكن أن يكون سالبًا إن سُجلت مشتريات قبل تمويلها؛ هذا يظهر العجز ولا يمنع تسجيل العملية. التواريخ بحسب الرياض. الإدخال يقبل الأرقام العربية والإنجليزية والفارسية، والمبالغ موجبة حتى منزلتين عشريتين. تستخدم قاعدة البيانات `numeric`، وتُرسل المبالغ إلى الواجهة كنصوص دون جمعها بأرقام JavaScript العشرية.

المخزون المحمي هو **الرصيد الحالي**. تاريخ العملية محاسبي للعرض والفرز، ولا ننفذ منعًا لرصيد سالب تاريخيًا عند إدخال عملية بأثر رجعي. لا توجد أرصدة افتتاحية مخفية: كلها صفر، وتمويل البداية يُسجل كمساهمة.

## منع التعارض والتكرار

تُقفل خانة المشروع أثناء الكتابة. يعدّل Trigger المخزون داخل المعاملة نفسها؛ فشل الفحص يلغي المعاملة كلها. يشمل ذلك تخفيض مشتريات سابقة أو حذفها. إذا تغيّرت عملية منذ فتحها، يُرفض الحفظ ويطلب التطبيق تحديثها. UUID ثابت لإعادة محاولة الإنشاء يمنع تكرار نفس العملية عند انقطاع الرد. لا يسمح بتعديل النوع من شاشة التعديل؛ تغييره متاح فقط قبل أول حفظ.

رفع الصور مرحلة تالية لحفظ المعاملة. إذا فشل رفع صورة، يبقى السجل محفوظًا وتظهر رسالة واضحة لإضافة الصور من التفاصيل؛ لا تعِد إدخال المعاملة. الحد 6 صور في الدفعة و12 صورة لكل عملية، وبحد 5 MiB للصورة، بصيغ JPG/PNG/WebP. استخدم «الأكثر توافقًا» في إعدادات كاميرا iPhone إذا كانت الصور HEIC. لا تُقبل SVG أو HTML أو الملفات التنفيذية.

## PWA على iPhone

بعد نشره في Cloudflare: افتح الموقع في Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية ← إضافة. وعلى Android استخدم خيار تثبيت التطبيق في المتصفح. يتضمن المشروع manifest وأيقونات 192 و512 وApple 180، واتجاه RTL، وsafe-area للشاشات ذات النتوء.

لا يُحفظ أي سجل أعمال في service worker. يخزن فقط صفحة تعذر الاتصال وأيقونتها. إذا كنت داخل التطبيق ثم انقطع الإنترنت تُعرض رسالة وتُمنع الكتابة. لا توجد مزامنة أو إدخالات بدون اتصال.

## الاختبارات

```bash
npm run check
npm run build
```

- اختبارات وحدات للأرقام والمبالغ وآثار أنواع العمليات.
- اختبار DOM للتنقل والحقول حسب نوع العملية؛ ليس بديلًا عن اختبار Safari الفعلي.
- اختبارات PostgreSQL معزولة باستخدام PGlite، تشمل الحسابات والصلاحيات وRLS والعمليات والتعديل والحذف وسجل المراجعة والبحث وتجاوز 50 عملية.
- اختبار تزامن باتصالين PostgreSQL مستقلين في `tests/concurrency.ts`. يحتاج قاعدة محلية جديدة اسمها يبدأ بـ `sheep_test`؛ يرفض الاتصال بمشروع مستضاف. لم يُنفذ في بيئة التسليم لعدم توفر PostgreSQL مستقل.
- خطوات الاختبار على iPhone ورفع المرفقات واستمرار البيانات بعد تحديث الصفحة في `docs/TESTING.md`. هذه البنود تحتاج حسابي الشريكين ولم تُعتمد بعد.

## تكلفة البداية والحدود

لا يعتمد المشروع على واجهة مدفوعة، أو مزوّد دخول مدفوع، أو نطاق خاص. تمت معاينة خطة منظمة Supabase وهي Free.

بحسب الصفحات الرسمية التي روجعت في 13 أكتوبر 2026: Supabase Free يوفر قاعدة 500 MB، وتخزين ملفات 1 GB، و5 GB نقل بيانات و5 GB نقل مخبأ، و50,000 مستخدم نشط شهريًا، ومشروعين نشطين كحد أقصى. قد يُوقف المشروع بعد أسبوع من عدم النشاط، ولا تشمل الخطة نسخًا احتياطية تلقائية. احتفظ بنسخ دورية من قاعدة البيانات والملفات، وراقب حصة الصور. Cloudflare Pages يقدم طلبات الملفات الثابتة مجانًا دون حد لعدد الطلبات؛ الحدود تشمل 500 بناء شهريًا و20,000 ملف في الموقع على Free. لا تتطلب العمارة وظائف Workers مدفوعة.

هذه حدود الخطط الحالية وليست ضمانًا لمجانية دائمة أو لاستمرارية الخدمة. لا ترقِّ الخطة ولا تفعّل ميزات مدفوعة تلقائيًا؛ إذا وصلت للحصة، قلل الصور أو انقل نسخة احتياطية أو راجع قرار الخطة أولًا.

## حساب الربح بالمتوسط المرجح

كل السجل منذ البداية فترة حسابية واحدة. المتوسط مرجّح بعدد الرؤوس وليس متوسطًا بسيطًا لأسعار الدفعات. يُستخدم المتوسط كامل الدقة لتقييم المخزون، ثم تُقرّب قيمته إلى هللتين عشريتين ويُحسب الربح منها؛ المتوسط المعروض مقرب إلى منزلتين فقط. إذا لم توجد مشتريات فالمتوسط صفر. عند نفاد المخزون تصبح قيمته صفرًا. الرؤوس الهالكة تخرج من العدد، فتدخل خسارتها ضمن الحساب تلقائيًا دون خصم تقديرها الاختياري مرة أخرى. رأس المال لا يؤثر في الربح. التعديل أو الحذف يعيد الحساب من السجلات الفعالة. لا توجد تقارير ربح لفترات مغلقة؛ إضافة مشتريات لاحقة تغيّر المتوسط التراكمي والنتيجة منذ البداية.

المثال المعتمد: شراء 10 رؤوس بـ10,000، بيع 6 بـ9,000، هالك رأس، مصاريف 500: المتبقي 3، متوسط الرأس 1,000، قيمة المخزون 3,000، وصافي الربح 1,500 ر.س.


## الحسابات في المرحلة الحالية
- واجهة دخول بالبريد وكلمة المرور فقط. إنشاء الحسابات واستعادتها بالبريد متوقفان في الواجهة.
- من Supabase Authentication → Users → Add user → Create new user أدخل البريد وكلمة المرور وفعّل Auto Confirm User. كرر للبريد الثاني المحدد في القائمة الخاصة.
- الاعتماد في partners تلقائي للحساب المؤكد إداريًا، ولا يحتاج إدخالًا يدويًا في جداول البيانات.
- عطّل Allow new users to sign up في إعدادات Auth المستضافة؛ config.toml محلي ولا يغيّر إعدادات المشروع المستضاف. الموصل لا يتيح تعديل هذا الخيار، ولم يُغيّر عن بعد.
- لا حاجة إلى SMTP للدخول بكلمة المرور. لا تحفظ كلمات المرور في جدول public أو في المستودع.
- رابط Sites الحالي خاص بالمالك؛ يلزم استضافة مناسبة للشريكين قبل الاستخدام المشترك.
